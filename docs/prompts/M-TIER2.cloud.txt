THREE CONTRACTS LANDED SINCE THIS BRIEF WAS WRITTEN AND ALL THREE SIT DIRECTLY
UNDER YOUR HANDS. Read them before you touch handoff.

1. FACING, NOT ADJACENCY — test/headless.js checkRigOutput. A belt hands its
   item to the ONE tile it faces, and a machine does the same, which is why a
   machine whose output points into the rig feeds it with no belt at all while
   the same machine parked against the rig pointing the wrong way delivers
   nothing. That asymmetry is deliberate and the director rejected the
   adjacency variant explicitly ("i want to go to the rig if the output is
   faced to the rig, not if it only is adjacent to it"). The reason is
   pedagogical, so it outranks convenience: if machines fed from any side while
   belts required facing, the game's own lesson about belts would be a lie.
   Whatever splitters, filters or underground pairs you add obey the same rule,
   and that test must still pass unmodified. If your design genuinely cannot
   hold it, STOP and report rather than relaxing it.

2. Sim.chain(run) reads machine rates to name the production bottleneck for the
   CHAIN panel, and it is PURE — no mutation, no run.rng (law 7), pinned by
   test/headless.js checkChain. Every new machine type you add needs a rate in
   that model, or it becomes invisible to the panel that teaches the chain: a
   splitter the player can see on the map but not in CHAIN is a hole in the
   game's only live explanation of itself. Extend checkChain alongside it.

3. THE TUTORIAL NOW TEACHES BELTS, and it landed hours before you were
   dispatched, so nothing else in this brief mentions it. js/tutorial.js runs a
   four-beat first-run induction on the live map, and TWO of those beats are
   yours: beat 3 gates on the player laying a belt from an extractor's output
   arrow to the rig, and beat 4 gates on ore actually arriving, through
   Sim.deliver(). A belt refactor that changes what counts as "laid" or what
   counts as "delivered" will strand a new player on a beat with no way
   forward, and it will do it silently, because the induction only runs on a
   profile with zero completed runs and NO scripted test plays like a beginner.
   Run the tutorial section of test/integration.js and keep it green; if you
   change belt handoff at all, drive the four beats yourself before you call it
   done. The first thing the game does with a new player is the last thing that
   should break.
